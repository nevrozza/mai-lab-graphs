# ЛР. Графы
### Матрица смежности и кратчайший путь алгоритмом Дейкстры

В проекте реализована работа с графом, который хранится с помощью матрицы смежности. Для поиска кратчайшего пути используется алгоритм Дейкстры.

По условию лабораторной работы нужно использовать представление графа через матрицу смежности и реализовать поиск кратчайшего пути.

> [!NOTE]
> После хранения графа в матрице основная работа происходит уже вокруг алгоритма Дейкстры: нужно поддерживать массив расстояний, отмечать обработанные вершины и запоминать предыдущие вершины, чтобы потом восстановить маршрут.

# Отчет по лабораторной работе по курсу "Фундаментальная информатика"

**Тема:** Графы. Представление графа и поиск кратчайшего пути.

**Цель:** Освоить представление графа в памяти программы и реализовать алгоритм поиска кратчайшего пути.

**Задание:** Представить граф с помощью матрицы смежности и реализовать алгоритм Дейкстры для поиска кратчайшего пути.

> **Представление графа:** матрица смежности.
>
> **Алгоритм:** кратчайший путь - Дейкстра.

## Идея и метод решения

Граф хранится в виде матрицы смежности. Строки и столбцы матрицы соответствуют вершинам графа, а значение в ячейке показывает наличие ребра и его вес.

Если между вершинами есть ребро, в матрице хранится его вес. Если ребра нет, используется специальное значение, которое означает отсутствие перехода. Это значение нужно выбирать аккуратно, чтобы не спутать отсутствие ребра с ребром нулевого веса.

Для поиска кратчайшего пути используется алгоритм Дейкстры. Он постепенно выбирает вершину с минимальным известным расстоянием от стартовой вершины и пытается улучшить расстояния до ее соседей.

> [!IMPORTANT]
> Алгоритм Дейкстры корректно работает только с неотрицательными весами ребер. Если в графе есть отрицательные веса, нужен другой алгоритм.

## Структура программы

Логически программу можно разделить на несколько частей:

- хранение графа в матрице смежности
- чтение количества вершин и ребер
- заполнение матрицы весами ребер
- проверка корректности введенных данных
- запуск алгоритма Дейкстры
- хранение текущих расстояний от стартовой вершины
- хранение информации о предыдущих вершинах для восстановления пути
- вывод результата

Матрица отвечает только за хранение графа. Сам поиск кратчайшего пути удобнее держать отдельно: так проще проверять ввод, запускать алгоритм и выводить результат.

## Алгоритм Дейкстры

1. Для всех вершин расстояние считается бесконечным
2. Для стартовой вершины расстояние устанавливается равным `0`
3. Все вершины изначально считаются необработанными
4. На каждом шаге выбирается необработанная вершина с минимальным текущим расстоянием
5. Для всех соседей этой вершины проверяется, можно ли улучшить расстояние
6. Если новый путь короче, расстояние до соседа обновляется
7. Для восстановления пути запоминается предыдущая вершина
8. Вершина помечается как обработанная
9. Алгоритм продолжается, пока есть достижимые необработанные вершины

## Тонкости реализации

В этой лабораторной важно не только получить длину кратчайшего пути, но и корректно обработать все состояния алгоритма.

При реализации нужно учитывать:

- правильно обозначить отсутствие ребра в матрице
- не спутать отсутствие ребра с ребром нулевого веса
- корректно выбрать следующую вершину с минимальным расстоянием
- не обновлять расстояния через уже недостижимые вершины
- хранить предыдущие вершины для восстановления маршрута
- обрабатывать случай, когда путь между вершинами отсутствует
- проверять границы номеров вершин
- не использовать отрицательные веса для Дейкстры

> [!IMPORTANT]
> Для вывода маршрута недостаточно знать только длину кратчайшего пути. Нужно дополнительно хранить предыдущую вершину для каждой вершины и потом пройти по этим данным от конечной вершины назад к начальной.

Кратко про обработку ошибок: программа учитывает некорректное количество вершин, неправильные номера вершин, отрицательные веса, отсутствие пути между выбранными вершинами и ошибки ввода. В таких случаях нужно вывести понятное сообщение, а не продолжать работу с поврежденными данными.

> [!NOTE]
> Матрица смежности удобна для проверки наличия ребра за `O(1)`, но при большом количестве вершин может расходовать много памяти, потому что хранит данные для всех пар вершин.

Примеры тестов:

| **Сценарий** | **Что проверяется** |
|:------------|:--------------------|

## Сложность

При использовании матрицы смежности и простого поиска минимальной необработанной вершины алгоритм Дейкстры работает за `O(n^2)`, где `n` - количество вершин.

| **Операция** | **Сложность** |
|:------------|:--------------|
| хранение графа | `O(n^2)` |
| проверка ребра между двумя вершинами | `O(1)` |
| поиск кратчайших путей | `O(n^2)` |
| восстановление пути | `O(n)` |
